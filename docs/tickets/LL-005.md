# LL-005 — GitHub Actions CI with Ephemeral Neon Branches


**Branch** `ci/ll-005-github-actions`

> Implement LL-005. Create CI for pull requests and pushes to `main`.
>
> Jobs: install (cached) → lint → typecheck → unit tests → build. Then a separate
> database-backed job:
>
> 1. Create an isolated Neon branch named `test/pr-<number>-run-<run_id>`.
> 2. Apply committed migrations. A migration failure fails the job immediately —
>    never caught and continued.
> 3. Seed deterministic test data.
> 4. Run integration tests.
> 5. **Delete the branch with `if: always()`** so failures do not leak branches.
>
> Also add a scheduled reaper workflow that deletes `test/*` Neon branches older than
> 24 hours. Neon branch limits are finite and a leaked-branch pileup will eventually
> block CI.
>
> Secrets: `NEON_API_KEY`, `NEON_PROJECT_ID`. Never echo their values, and ensure they
> are not exposed to workflows triggered by forked pull requests.
>
> Pin the Node version to match `.nvmrc` and Vercel. Add concurrency groups so a new
> push cancels the superseded run.
>
> CI must fail on: lint, types, unit tests, integration tests, migration failure, or
> build failure.
>
> If Neon credentials are unavailable in this environment, implement the complete
> workflow configuration and document exactly which GitHub secrets a human must add.
> **Do not hard-code substitutes, and do not silently skip the database job** — make it
> fail visibly with an actionable message.
>
> Document the CI workflow in `/docs/TESTING.md` and `/docs/DEPLOYMENT.md`.
