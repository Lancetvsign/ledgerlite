# LL-084 — Bank import: the suggested account is actually pre-selected

**Branch** `feat/ll-084-import-suggestion-preselect` · **Status** implemented · **Origin** product owner,
after the first real statement: "it makes a recommendation and does not actually select the category. If
there is a recommended category I want it actually selected so I just have to select post."

## §11 — End-of-ticket report

**Ticket:** LL-084 — map the model's free-text category to a chart account robustly so the review
picker is pre-selected whenever the recommendation is unambiguous.
**Root cause:** the picker was already bound to `suggestedAccountId`, but that id was set only when the
model's text matched an account name or number EXACTLY. The model answers "6300 · Office Supplies",
"Office supplies", "Rent (6500)" or "Advertising and Marketing"; each failed the exact match, so the
grey "suggested:" hint rendered and the picker stayed on "Choose account…".
**Files changed:** `src/server/bank-import/categorize.ts` (new pure mapper, four tiers: exact →
number token → normalised name → unique containment; ambiguity returns null, never a guess);
`src/server/bank-import/index.ts` (uses it; per-batch breadcrumb with counts only:
history/model/unmapped/uncategorised); this ticket; ADR-034 amendment.
**Migrations created:** none. **DB constraints added:** none.
**Tests added:** `tests/unit/bank-import-categorize.test.ts` — 13 phrasings that must map, 5 that must
not, and the twin-name determinism cases. Existing integration/e2e suites cover the wiring (history
first, then model, exact names still map).
**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ (`npm run ci`); bank-import e2e ✓ locally.
**Accounting implications:** none — a suggestion is still only a default; posting uses what the
reviewer confirms, and corrections keep feeding the history-first tier (LL-080).
**Security implications:** none; the new log line carries counts only (§9).
**Decisions made not specified in the ticket:** an ambiguous phrase (two accounts both plausible)
leaves the picker empty rather than guessing — a wrong pre-selection costs more than an empty one.
**Known limitations:** synonyms ("Fuel" → "Vehicle Expenses") are not inferred; the model must name the
account. Those are learned once corrected (history tier).
**Recommended follow-up:** if production breadcrumbs still show `unmapped > 0`, tighten the prompt to
answer with the account number only.
