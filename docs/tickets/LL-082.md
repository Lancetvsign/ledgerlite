## §11 — End-of-ticket report

**Ticket:** LL-082 — delete (archive or purge) a company, OWNER-only, with typed confirmation.
**Files changed:** `src/server/rbac/capabilities.ts` (+`company.delete`, OWNER only);
`src/server/companies/{index,errors}.ts` (`deleteCompany`, `PURGE_ORDER`, `CompanyError`);
`src/server/authorization/company-context.ts` (`clearActiveCompanyIf`); `src/db/schema/audit.ts`
(+`COMPANY_ARCHIVED`); `src/app/account/{page,actions,company-panel}.tsx` (Delete… disclosure form,
notices); ADR-038; this ticket.
**Migrations created:** `0034_company_archived.sql` — adds the enum value `COMPANY_ARCHIVED` to
`audit_action`. Expand-only; nothing else.
**DB constraints added:** none (the existing `ON DELETE restrict` FKs and the append-only audit trigger
are what shape the archive-vs-purge rule).
**Tests added:** `tests/integration/company-delete.test.ts` — archive on posted history (hidden,
fail-closed, rows retained, audited); archive on audit-only history; second delete denied; purge removes
every tenant row and leaves another tenant intact; `PURGE_ORDER` ≡ every `company_id` table minus
`audit_events`; exact-name confirmation; ADMIN / stranger / malformed id denied identically;
authorization precedes the name check (no oracle). `tests/integration/isolation.test.ts` — delete attempt
registered on the `companies` descriptor. `tests/unit/rbac.test.ts` — matrix updated.
`tests/e2e/company-delete.spec.ts` — purge through the UI; wrong name deletes nothing.
**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ locally (`npm run ci`); e2e (company-delete)
✓ locally; integration on CI's ephemeral branch (migration 0034 is not applied to the shared dev branch).
**Accounting implications:** none to the ledger. A company with any posted entry is never physically
removed; its journal, audit and document rows persist unchanged.
**Security implications:** new OWNER-only capability; the typed name is compared only after
authorization; every denial is the uniform `AuthorizationDenied`; the purge log carries ids only.
**Decisions made not specified in the ticket:** archive also when the company has an audit trail but no
postings (the audit log is append-only at the database, so a purge is structurally impossible then);
whitespace around the typed name is forgiven; the active-company cookie is cleared when it named the
deleted company (a stale pointer already yields no company, so this is cosmetic).
**Known limitations:** no reactivation of an archived company; no ownership transfer first; the
disclosure uses a native `<details>` so the confirmation form has no client-side validation beyond
`required`.
**Recommended follow-up:** reactivate/undo for archived companies (OWNER); retention-driven purge of
archived companies as a reviewed migration.
