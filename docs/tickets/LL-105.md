# LL-105 — Review progress is saved: per-line drafts, batches show "in progress"

**Branch** `feat/ll-105-review-drafts` · **Status** implemented · **Origin** owner request during the Gate 7 manual acceptance (2026-09-24): "When I am reviewing a statement or a credit card, have it save and mark as in progress instead of resetting if I leave the statement before completion." · **Decision** ADR-045 · **Migration** 0043

Every per-line choice on the review screen (action, account, document, counterpart) and on the shared "take"
screen (tick, account) is now autosaved as a **draft** — one row per STAGED line per drafting company — and
restored on the next load. The "Recent imports" list and the review page show New / In progress / Complete.
A draft never posts anything and cannot outlive the staged state (two triggers).

**Accounting implications:** none — a draft is scratch state with no ledger effect; posting is unchanged and still
re-validates everything (a draft account or document is only a pre-filled choice).
**Security implications:** drafts are scoped to the drafting company and read only through the authorized views;
the shared screen's drafts need the same visibility as the shared view itself; an invisible statement reads as
not-found. No existence leak: a foreign account id is silently dropped, never echoed.
**Decisions made that were not specified in the ticket:** drafts are per company, not per user (one owner, one
review); an autosave never fails the page — invalid pieces are dropped and decided lines skipped; "Reset to
suggestions" still means the server's suggestions, not the saved draft.
**Known limitations:** a line un-ignored later (LL-089) or given back (LL-097) returns to STAGED with no draft —
the page reloads with the suggestion. Autosave needs JavaScript; the "Save progress" button is the same action.

builds on these drafts for the "waiting for a match" state.
