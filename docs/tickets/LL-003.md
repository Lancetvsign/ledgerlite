# LL-003 — Test Foundation


**Branch** `test/ll-003-test-foundation`

> Implement LL-003. Configure the testing architecture: Vitest for unit and integration,
> Playwright for end-to-end.
>
> **The production guard is the critical deliverable.** Before any database-backed test
> opens a connection, it must verify the target database is not production and abort
> loudly if it is. Do not rely solely on an environment variable name — check the actual
> connection target (branch/host/database name) against an explicit allowlist, and
> require an opt-in `APP_ENV=test`. Write a test that proves the guard aborts when
> pointed at a production-shaped URL.
>
> Separate `tests/unit`, `tests/integration`, `tests/e2e`, `tests/fixtures`,
> `tests/helpers`. Integration tests get a per-suite clean database state — decide and
> document whether that is transaction rollback per test or truncate-and-reseed, and
> justify the choice for an accounting test suite.
>
> Deterministic synthetic fixtures only. No real customer or financial data, ever.
> Fixture money values are strings, never JavaScript numbers.
>
> **Playwright authentication:** Better Auth arrives in LL-010, so build the seam now —
> a global setup that seeds a known test user, performs login once, saves
> `storageState`, and reuses it across specs. Stub it for now with a clear TODO
> referencing LL-010 so the E2E suite does not stall later.
>
> Scripts: `test`, `test:unit`, `test:integration`, `test:e2e`.
> Deliver at minimum one unit test, one database integration smoke test, and one
> browser smoke test that all pass.
>
> Document conventions in `/docs/TESTING.md`, including the rule that tests are never
> weakened to accommodate failing code.
