# LL-104 — Structural line immutability: no line may be added to a posted entry

**Branch** `feat/ll-104-line-immutability` · **Status** implemented · **Origin** `docs/GATE-7.md` §6 M5 (with 5c L4, 5c N4) · **Decision** ADR-044 · **Migration** 0042

Gate 7 M5: `journal_lines_immutable` fired on UPDATE/DELETE only, so raw balanced lines could be appended to
any POSTED or REVERSED entry — on a POSTED `INTERCOMPANY` entry the Due-account allow-list admitted them, which
made ADR-043's "structural mirror" claim untrue against raw SQL. The stub proposed a BEFORE INSERT guard with
a session-local escape for the engine. **Built without the escape**: the guard is unconditional and the engine
posts by transition (DRAFT → lines → POSTED). Plan mode was used (schema change); the owner approved the plan.

**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ (`npm run ci`); e2e (journal, bank-import) — see the
PR checks; integration on CI's ephemeral branch (local integration truncates the dev DB where real data lives).
**Accounting implications:** invariant 3 is now structural in full — a posted or reversed entry's line set
cannot change by any path. The intercompany mirror (ADR-043) is structural again as amended by LL-101: the
database can hold no single-sided group other than a mark, and no line can join a posted entry. A posting is
one transaction of three statements instead of two; nothing observable changes for callers (same return
shape, same errors, same audit rows, same gapless numbering).
**Security implications:** none new; the change removes a raw-SQL corruption path rather than adding surface.
**Decisions made that were not specified in the ticket:** no session-local escape (ADR-044 explains why: a
GUC is conventional and `SET LOCAL` outlives the engine's statements); the reversal CHECK is bidirectional;
the period guard on the transition is a second trigger rather than a rewrite of 0010's.
**Known limitations:** a raw DRAFT → lines → POSTED sequence is, by design, still possible — it *is* posting,
and the database judges it exactly as it judges the engine (period, control accounts, balance, links). A
"both sides" structural rule for intercompany groups (5c N5) remains conventional: a one-member group is
legal because "in transit" is.
**Recommended follow-up:** none required. The owner's remaining Gate 7 items are the PERSONAL account rule
(§7 item 3) and the manual acceptance (§4).
