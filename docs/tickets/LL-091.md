# LL-091 — System accounts can never be statement accounts (Gate 6 H2)

**Branch** `feat/ll-091-system-accounts-never-statement` · **Status** implemented · **Origin** Gate 6
accounting review HIGH-1 (+ security NOTE-5). Design: ADR-025 amendment.

## Problem
`updateAccount` let an ADMIN change `cashFlowCategory` / `accountSubtype` on a system account, after which
`isStatementAccount` admitted Accounts Receivable (as CASH) or Accounts Payable (as `credit_card`) to Bank
Import and Reconciliation. Import lines then posted to a control account with no document behind them; the
control-account trigger guarded only `JOURNAL_ENTRY`.

## §11 — End-of-ticket report

**Ticket:** LL-091 — system accounts are never statement accounts; their subtype and cash-flow section are
fixed; the control-account lock covers imported and opening-balance sources at the database.
**Files changed:** `src/server/accounts/statement-account.ts` (system role → never a statement account);
`src/server/bank-import/index.ts` and `src/server/reconciliation/index.ts` (select the role; Retained
Earnings excluded from import categories, also in the review page); `src/server/accounts/index.ts`
(`updateAccount` refuses subtype/cash-flow changes on system accounts, unchanged values pass);
`src/app/accounts/account-row.tsx` (system rows show the fixed fields as text) and `page.tsx` (notice);
migration 0037; ADR-025 amendment; this ticket.
**Migrations created:** `0037_control_lock_covers_imports.sql` — `CREATE OR REPLACE` of
`assert_no_manual_post_to_control_account` and `assert_no_manual_relabel_to_control_account` so the guarded
sources are `JOURNAL_ENTRY`, `BANK_IMPORT`, `OPENING_BALANCE`. Triggers unchanged; expand-only; idempotent.
**DB constraints added:** the widened trigger guard (structural).
**Tests added:** `tests/integration/control-account-guard.test.ts` — A/R flagged CASH and A/P flagged
credit-card via raw SQL are refused by `stageImport` (`INVALID_BANK_ACCOUNT`) and `startReconciliation`
(`NOT_A_BANK_ACCOUNT`); raw `JOURNAL_ENTRY`/`BANK_IMPORT`/`OPENING_BALANCE` lines into A/R are refused by the
database while `CUSTOMER_PAYMENT`/`INVOICE` lines insert; `updateAccount` on A/R refuses a cash-flow or
subtype change but renames with unchanged values. `tests/integration/gl-regression.test.ts` — **GL-T028**.
`tests/integration/bank-import.test.ts` — Retained Earnings not pickable. `tests/e2e/accounts.spec.ts` — the
A/R edit form shows fixed fields and no cash-flow select; rename saves.
**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ (`npm run ci`); accounts e2e ✓ locally;
integration and the migration on CI's ephemeral branch.
**Accounting implications:** the aging ⇔ control tie is now structural against imports and opening
balances as well as manual entries; nothing changes for documents.
**Security implications:** closes Gate 6 H2; an ADMIN can no longer reclassify a control account into an
importable one.
**Decisions made not specified in the ticket:** unchanged subtype/cash-flow values are accepted so the row
