# LL-108 — Every report figure drills down to the transactions behind it

**Branch** `feat/ll-108-report-drilldown` · **Status** implemented · **Origin** owner request (2026-09-25): "Make it so I can click on a number in a report and it will drill down to the transactions that make up that number." · **Decision** ADR-040 amendment · **Migration** none

Every figure on a report is now a link to what makes it up. An account's figure opens the **account
register** (LL-084 / ADR-040 — the ledger-derived detail behind every balance, whose rows already link to
each source document and journal entry) for the report's window; a customer's or vendor's figure opens their
**statement**; a computed line (net income, prior retained earnings) opens the **income statement** that
computes it; a dashboard headline opens the report it came from; a recent-activity amount opens its entry.

## §11 — End-of-ticket report

**Ticket:** LL-108 — report drill-down.
**Files changed:** `src/app/reports/drill.tsx` (new: `DrillLink`, `registerHref`, `incomeStatementHref`, `yearStart`,
`dayBefore`), `trial-balance/page.tsx` (debits, credits and balance → register, Jan 1 of the as-of year → as-of),
`balance-sheet/page.tsx` (accounts → register, fiscal-year start → as-of; prior retained earnings → income statement
from the beginning of time to the day before the fiscal year; current net income → income statement for the fiscal
year), `income-statement/page.tsx` (accounts → register for the period), `cash-flow/page.tsx` (adjustment lines →
register for the period; net income → income statement), `aging/page.tsx` and `ap-aging/page.tsx` (name, buckets
and total → the customer / vendor statement as of the date), `intercompany/page.tsx` + `src/server/reports/
intercompany.ts` (this company's Due from / Due to → their registers; the row carries the pair account ids),
`src/app/dashboard/page.tsx` (headline figures → the reports; recent-activity amounts → the entry).
**Migrations created:** none. **DB constraints added:** none.
**Tests added:** e2e `reports.spec.ts` — trial balance → register (same closing figure, both lines), balance sheet →
register and → income statement, income statement → register, aging → customer statement, dashboard → aging.
Existing report e2e assertions (row text, totals) are unchanged: the links carry the same text.
**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ (`npm run ci`); reports e2e locally; integration on CI
(the intercompany row gained two nullable ids; existing `toMatchObject` assertions are unaffected).
**Accounting implications:** none — reads only. The register's closing balance equals the report's figure whatever the
window's start, because its opening balance carries everything before it; the trial balance links use January 1st of
the as-of year (the trial balance carries no fiscal-year start), the balance sheet uses the company's fiscal-year start.
**Security implications:** none new — every target screen re-authorizes (`report.view`) and scopes to the session's
company; the ids in the links are the company's own account / customer / vendor ids, which the report already showed.
**Decisions made that were not specified in the ticket:** subtotals and grand totals (total assets, gross profit, cash
totals) are not links — they are sums of rows that are; "prior retained earnings" drills to an all-time income
statement ending the day before the fiscal year (the ledger posts no closing entry, ADR-030); the counterpart's
figures on the intercompany report are not links (they live in the other company's books).
**Known limitations:** none.
**Recommended follow-up:** a "back to report" breadcrumb on the register and statement screens.
