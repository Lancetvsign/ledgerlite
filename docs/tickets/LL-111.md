# LL-111 — Reconcile from an imported statement: prefilled figures, pre-ticked lines

**Branch** `feat/ll-111-reconcile-from-import` · **Status** implemented · **Origin** owner's choice for LL-111 (2026-09-27), from the follow-ups recommended by LL-109 · **Decision** ADR-036 amendment · **Migration** 0047

From a statement's review page, "Reconcile this statement" opens the reconciliation start form prefilled from
what the statement printed (account, closing date, ending balance — all editable); starting it ticks and saves
the ledger lines the statement posted, so the difference is usually zero at once. The reviewer completes.

**Tests added:** integration `reconcile-from-import.test.ts` — defaults for a bank (printed date and ending) and a card (ending

**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ (`npm run ci`); bank-import + reconciliation e2e locally; integration on CI.
**Accounting implications:** none — a reconciliation is a control, not an entry; ticks go through the existing eligibility rule;

**Security implications:** `reconciliation.view` for the defaults, `reconciliation.complete` for the ticks; a foreign batch reads

**Decisions made that were not specified in the ticket:** the canned test statements now print a zero opening balance and a
closing date (their totals still verify, LL-109); a statement with no printed date falls back to its latest line, flagged; an
unreadable printed date is dropped without dropping the totals.
**Known limitations:** statements uploaded before this deploy have no stored closing date (the latest line is used) and, before
LL-109, no ending balance (entered by hand); a reversed-and-reposted line's reversal pair is not auto-ticked (it nets to zero).
