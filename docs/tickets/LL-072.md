# LL-072 — Financial statements (Balance Sheet + Income Statement)

**Branch** `feat/ll-072-financial-statements` · **Status** Implemented (see §11) · **Origin** roadmap
(primary statements on top of the trial balance, now that opening balances exist).

> Two read-only derived reports: a **Balance Sheet** (as-of) and an **Income Statement / P&L** (date range),
> computed from `journal_lines` like the trial balance — no schema change, no posting path. The Balance
> Sheet derives net income into equity (period-close posts no closing entry), split at the fiscal-year start
> into prior retained earnings + current-year net income. Full design in ADR-030.

**Test results:** lint ✓ / typecheck ✓ / unit ✓ (182) / build ✓ (`npm run ci`). The financial-statements
suite is DB-backed (integration) and runs on the PR's CI shards, not locally against the shared dev branch.

**Accounting implications:** statements are fully derived from journal lines (invariant 2) — no stored
figure can drift. The Balance Sheet derives net income into equity because close posts no closing entry, so
Assets = Liabilities + Equity holds off the trial-balance identity; the split into prior retained earnings vs
current-year net income uses the company's `fiscalYearStartMonth`. The Retained Earnings account remains an
empty shell shown as its own equity row.

**Security implications:** both services enforce `report.view` (granted to all members, checked server-side);
company comes from the authorized session context, never a param. Reads only.

**Decisions made not specified in the ticket:** the fiscal-year earnings split (product-owner choice, ADR-030);
grouping by `account_type` with subtype subgrouping deferred (subtype is free text); the service returns
`liabilitiesAndEquityTotal` so the page recomputes nothing (no client-side money math).

**Known limitations:** no subtype subgrouping (Current/Fixed assets), no comparative columns, no cash-flow
statement, no export/PDF; "retained earnings" is derived (no closing workflow writes to account 3900).

**Recommended follow-up:** subtype subgrouping + comparative (prior-period) columns; a cash-flow statement;
a fiscal-aware default period for the Income Statement (default `from` to the company's fiscal-year start
rather than calendar Jan 1, so its default "current year" matches the Balance Sheet's — needs the company's
`fiscalYearStartMonth` in the page/report-context); optionally a year-end closing-entry workflow (which would
post net income into Retained Earnings).
