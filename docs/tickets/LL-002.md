# LL-002 — Neon + Drizzle Foundation and Migration Framework


**Branch** `feat/ll-002-database-foundation`
**Use plan mode.**

> Implement LL-002. Integrate Neon PostgreSQL via Drizzle ORM and Drizzle Kit.
>
> **Read ADR-001 first and implement exactly what it decided.** The dual-driver split
> is not optional and not a detail:
>
> - `src/db/index.ts` exports `db` (HTTP client, `drizzle-orm/neon-http`) for reads and
>   single-statement writes, and `dbTx` (Pool client, `drizzle-orm/neon-serverless`)
>   for anything requiring a transaction.
> - Document at the top of that file, in a comment a future agent cannot miss, that
>   financial write paths use `dbTx` exclusively and why.
> - Add an ESLint `no-restricted-imports` rule (or equivalent boundary check)
>   preventing `src/server/ledger/**` from importing the HTTP client.
>
> Server-only enforcement: `DATABASE_URL` must never reach browser code. Use
> `import 'server-only'` in the db module and verify a client component importing it
> fails the build. Report that verification.
>
> **Migration framework:**
> - `drizzle.config.ts` with migrations in `drizzle/migrations`, deterministic naming.
> - A migration runner that acquires a PostgreSQL advisory lock before applying and
>   releases it after, so concurrent runners serialize rather than race. Test this by
>   launching two runners simultaneously against a clean database and confirming
>   exactly one applies and neither corrupts.
> - Scripts: `db:generate`, `db:migrate`, `db:studio`, `db:check`.
> - **`drizzle-kit push` must not appear in any script.** Document the prohibition and
>   the reasoning in `/docs/DATABASE.md`.
>
> Create one trivial non-financial table (e.g. `_health`) purely to validate
> connectivity and the migration path. No accounting entities.
>
> Behavior when `DATABASE_URL` is missing: fail immediately with a clear message that
> does not echo any connection string or partial credential. Test this.
>
> **Tests:** apply all migrations to a clean database; then apply them again and
> confirm the second run is a no-op rather than an error or a duplicate object.
>
> Update `/docs/DATABASE.md`, `/docs/DEPLOYMENT.md`, `.env.example`.
> Use only your own Neon development branch. Never production credentials.
