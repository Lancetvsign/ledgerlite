# LL-109 — A statement's own totals must reconcile to the extracted lines; re-analyse, then correct

**Branch** `feat/ll-109-statement-totals` · **Status** implemented · **Origin** owner request (2026-09-25): "When a statement is uploaded the system needs to verify that the transaction totals equal the total deposits and credits on the statement, or check the math: beginning balance plus credits minus debits equals the ending balance on the statement. If it doesn't match it needs to be re-analysed and corrected." · **Decision** ADR-034 amendment · **Migration** 0045

## §11 — End-of-ticket report

**Ticket:** LL-109 — statement totals as the extraction's control: verify, re-analyse once, then show the gap for correction.

**DB constraints added:** none.
**Tests added:** unit `bank-import-verify.test.ts` (verified / each mismatch with exact differences / partial figures / not
stated / card signs / 4-dp exactness, never a number) and `bank-import-extract.test.ts` (summary read and normalised; a first
pass that reconciles makes one call; a mismatch makes exactly one more call whose prompt carries the figures and not the model's
rows; the reconciling pass wins; two failing passes return the second with attempts 2). Integration `bank-import-verify.test.ts`
(figures stored; verified; misread → mismatch on the right checks with exact differences → corrected → verified; a bogus subtotal
ignored → verified while a posted line still counts; rows-only extractors → not stated; a malformed summary dropped, rows kept;
the list's verdict). E2E: verified → a wrong correction shows the mismatch and the differences, the warning and the list badge →
corrected back → verified.
**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ (`npm run ci`); bank-import e2e locally; integration on CI.
**Accounting implications:** none to the ledger — nothing posts by machine. The check makes a dropped, merged or misread line
visible before it posts, which is where the reconciliation problems of LL-107's motivation came from.
**Security implications:** the re-analysis prompt carries the statement text (already sent on the first pass) and the
discrepancy figures only; logs carry counts, statuses and differences — never a description, a row or the text (§9).
**Decisions made that were not specified in the ticket:** one automatic re-analysis, not a loop (each pass is a billed model
call; the second already carries the exact discrepancy); posting is warned, not blocked, while the totals disagree (a statement
whose printed totals are wrong, or that prints none, must remain importable); card balances are taken in the import account's
sign convention so one arithmetic rule serves banks and cards; an IGNORED line does not count (it was never a transaction).
**Known limitations:** a statement that prints only a beginning OR an ending balance cannot be arithmetic-checked (both are
needed); the credits/debits checks still run. The re-analysis is only as good as the second reading — the panel is the backstop.
**Recommended follow-up:** feed the stated ending balance into the reconciliation screen as the default statement balance.
