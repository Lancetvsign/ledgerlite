# LL-024 — Chart of Accounts UI


**Branch** `feat/ll-024-coa-ui`

> Implement LL-024: chart of accounts screens. Keep the UI simple — this sprint is
> about correctness, not visual design.
>
> Authorized users can view, search, create, edit permitted fields, and deactivate
> accounts. Display account number, name, type, subtype, and status.
>
> **Display no balances.** There are none to display, and a placeholder or a
> client-computed total would misrepresent the data model. If a balance column feels
> missing, that is LL-034's job and it derives from journal lines.
>
> Respect the capability system: `account.view` to see, `account.manage` to modify.
> `READ_ONLY` sees the list and no mutation controls — and the server refuses the
> mutation regardless of what the UI renders. UI-level permission checks are cosmetic;
> the server is authoritative. Verify both layers.
>
> A user must not reach another company's accounts by editing a URL. Test this
> specifically, and register the UI routes in the LL-014 isolation harness.
>
> System accounts render as protected and cannot be deleted or have their
> `system_account_type` reassigned through the UI.
>
> **E2E tests:** view list, search, create, edit, deactivate, permission-denied path,
> and cross-company URL manipulation denied.
