# LL-075 — Dashboard (financial home screen)

**Branch** `feat/ll-075-dashboard` · **Status** Implemented (see §11) · **Origin** roadmap (a home screen
tying the reports together).

> A read-only `/dashboard` composing the existing report services into headline stats (cash, A/R, A/P, net
> income, position) plus a recent-activity feed. Linked from `/account`. Design in ADR-033.

---

## §11 — End-of-ticket report

**Ticket:** LL-075 — dashboard.
**Branch:** `feat/ll-075-dashboard`

**Files changed:**
- `src/server/ledger/queries.ts` (+ barrel `index.ts`) — new `listRecentEntries` + `RecentEntry` type.
- `src/app/dashboard/page.tsx` — the dashboard (stat-card grid + recent activity + report links).
- `src/app/account/page.tsx` — a prominent `Dashboard →` link atop the nav.
- `docs/DECISIONS.md` ADR-033; `docs/tickets/LL-075.md`.

**Migrations created:** none (read-only feature, no schema change).
**DB constraints added:** none.

**Tests added:**
- `tests/integration/recent-entries.test.ts` — `listRecentEntries` newest-first, limit honoured,
  company-scoped, correct per-entry total, non-member denied (`report.view`).
- `tests/e2e/dashboard.{setup,spec}.ts` — a fresh company with an invoice + partial payment; open the
  dashboard from `/account` and assert `dashboard-cash` 200.0000, `dashboard-ar` 300.0000,
  `dashboard-net-income` 500.0000 (exact NUMERIC strings, UI never reformats) and two recent-activity rows;
  plus an unauthenticated redirect to `/sign-in`.

**Test results:** lint ✓ / typecheck ✓ / unit ✓ (182) / build ✓ (`npm run ci`). The recent-entries
integration test and the dashboard e2e run on the PR's CI (integration shards + e2e).

**Accounting implications:** none new — every figure is derived from the existing report services (balances
from journal lines, invariant 2); the dashboard reconciles with the full reports it links to. `endingCash`
from the cash-flow service supplies total cash; the balance sheet supplies the fiscal-year start bounding
the year-to-date figures.

**Security implications:** the page uses `requireReportContext` (auth + active-company redirects) and every
composed service enforces `report.view`; `listRecentEntries` is gated on `report.view` too. Company from the
session context. Reads only.

**Decisions made not specified in the ticket:** `/dashboard` route (not `/`, which `smoke.spec.ts` guards;
not replacing `/account`); `listRecentEntries` gated on `report.view` not `journal.view` for a consistent
summary surface; a fixed as-of-today / fiscal-YTD snapshot (no on-dashboard date pickers — the full reports
carry those). Recorded as ADR-033.

**Known limitations:** several service calls per load (no single aggregate endpoint); no charts, configurable
widgets, or per-user preferences; recent feed is a flat last-10 (no pagination).

**Recommended follow-up:** a single aggregate summary query if load time matters; charts/sparklines;
comparative figures once the statements gain prior-period columns.
