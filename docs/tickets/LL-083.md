**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ locally (`npm run ci`); integration and e2e on
CI's ephemeral branch (migration 0035 is not applied to the shared dev branch); e2e re-run locally once
LL-082 merged and the dev branch was migrated — see PR.
**Accounting implications:** none to the ledger. A template never posts; new companies still receive
the four required system accounts; existing companies never change.
**Security implications:** new OWNER-only capability; one documented unauthorized read limited to the
flagged row and to chart structure; the app layer never learns the template's identity; every denial is
the uniform `AuthorizationDenied`.
**Decisions made not specified in the ticket:** the master is a real company rather than a separate
table (the owner's wording, and it reuses RBAC/audit/UI); one template only; the zero-postings
invariant; settings copied from the template override the create input; settings locked after posting;
the required-accounts safety net; any owner may claim the empty slot (no instance admin exists).
**Known limitations:** no re-sync of existing companies; customers/vendors/documents are not copied;
the settings editor appears only on the template row; a foreign template blocks the e2e (it skips).
**Recommended follow-up:** an instance-admin role if the app is ever multi-operator; per-user templates.
