**Test results:** lint ✓ / typecheck ✓ / unit ✓ (275) / build ✓ (`npm run ci`); e2e ✓ locally
(organizations, company-template, company-delete, bank-import); integration + migration on CI.
**Accounting implications:** none to any figure today. New: two system roles whose accounts can be
moved only by an `INTERCOMPANY` posting or its reversal, so a pair always mirrors across the two
companies; one currency per organization.
**Security implications:** every organization operation is authorized in a company; an
organization id the actor has no stake in is indistinguishable from a non-existent one; no
organization-level role exists.
**Decisions made not specified in the ticket:** `company.organization` capability instead of reusing
`company.delete`; the trigger is an allow-list (not "treat like A/R"), closing deposit / bill-payment
/ write-off paths at once; pair accounts are deactivated on leave (ADR-006) and reactivated on rejoin;
a member cannot be archived either (an archived member could never leave); existing companies start
with no organization.
**Known limitations:** pair account names ("Due from <legal name>") do not follow a later rename —
identity is `intercompany_company_id`, and the UI of LL-097/098 should label by the live name.
**Recommended follow-up:** LL-097 (assign / personal on shared card statements), LL-098 (intercompany
report + GL-T029), LL-099 (bank transfers + settlement).
