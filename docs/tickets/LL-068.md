# LL-068 — Accounts Payable in the required (system-only) chart

**Branch** `feat/ll-068-ap-required-account` · **Status** Backlog · **Origin** Gate 5 (correctness
finding 7). LOW / functional-gap, fails closed.

> `REQUIRED_SYSTEM_ACCOUNTS` (`src/server/accounts/default-coa.ts`) lists A/R but **not A/P**, so a
> company created on the `'system-only'` chart has no Accounts Payable control account. Every A/P
> document then fails with `AP_ACCOUNT_NOT_CONFIGURED` until `installDefaultChartFor('standard')`
> runs. The `'standard'` chart is fine (it seeds 2000 Accounts Payable, tagged by migration 0022);
> only the minimal chart is short.
>
> ### Approach
> Add `ACCOUNTS_PAYABLE` to `REQUIRED_SYSTEM_ACCOUNTS` so every company — minimal or standard — has
> an A/P control from creation, mirroring A/R. Decide (ADR note) whether existing `'system-only'`
> companies get a backfill migration (like 0022 did for A/P numbering) or A/P is created lazily on
> first use. Fails closed today, so this is correctness-of-completeness, not a live corruption.
>
> ### Tests
> A `'system-only'` company can raise and pay a bill end to end without manually creating A/P;
> `default-coa` unit test asserts A/P is in the required set.
