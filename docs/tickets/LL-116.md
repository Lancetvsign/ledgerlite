# LL-116 — Choose the date of an undone posting's reversal

**Branch** `feat/ll-116-undo-date` · **Status** implemented · **Origin** owner's choice for LL-116 (2026-09-28), the follow-up LL-110 recommended · **Decision** ADR-044 amendment · **Migration** none

"Undo posting" on a statement line now has a date beside it. The reversal is dated there, anywhere from the
original posting date up to today. The screen proposes the posting's own date while its period is open, so the
correction lands in the same period as the mistake and that period's reports show the fix. Otherwise it
proposes today, as before.

**Tests added:** isolation — `undoDateDefaults` denied to another company's user. Integration `correct-posted.test.ts` — a reversal back-dated to the original date lands there and the

**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ (`npm run ci`); integration and e2e on CI.
**Accounting implications:** a back-dated reversal changes the reports of the period it lands in, as a correction
should; it is refused in a closed period, so a closed period's figures never move. Reversals still never predate the
entry they reverse.
**Security implications:** unchanged — `journal.post`; the date is validated as a calendar date and range-checked in
the service; the proposal helper (`undoDateDefaults`) is gated on `journal.post` like the review it serves and reads only the company's timezone and period statuses.
**Decisions made that were not specified in the ticket:** the range is the original posting date to today; the
default is the posting's date when its period is open; the service's default stays today for other callers.
**Known limitations:** the manual "Reverse" page (LL-110) keeps its own date field, defaulting to today.
