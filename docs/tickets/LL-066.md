# LL-066 — Close the control-account lock's document-source & reversal bypasses

**Branch** `feat/ll-066-control-lock-completeness` · **Status** Backlog · **Origin** Gate 5
(correctness finding 1 + finding 5; security LOW-2). Priority: **HIGH-adjacent** — it defeats the
release-gate invariant (aging⇔control) from the SERVICE layer, though not from the browser today.

> The control-account guard (0018, generalized in 0023) blocks a manual A/R or A/P line only when
> the parent entry's `source_type = 'JOURNAL_ENTRY'`. Two service-layer paths still move a control
> account without its subsidiary:
>
> 1. **`postJournalEntry` accepts any `sourceType`.** `src/validation/journal.ts` lets a caller pass
>    `'BILL_PAYMENT'`/`'EXPENSE'`/`'OPENING_BALANCE'`/etc. with an A/P line; the 0023 trigger only
>    checks `= 'JOURNAL_ENTRY'`, so it passes. Fix: the *manual* posting entry point must pin
>    `sourceType = 'JOURNAL_ENTRY'` (or reject any document source type presented without the owning
>    document). Only the journal UI calls it and it already hardcodes `'JOURNAL_ENTRY'`, so no
>    legitimate caller regresses.
> 2. **`reverseJournalEntry` will reverse a document's entry.** An ACCOUNTANT can reverse a bill's
>    `EXPENSE` entry or a `BILL_PAYMENT` entry directly, moving A/P while the bill/aging does not.
>    Fix: `reverseJournalEntry` refuses when the target entry's `source_type` is a document type —
>    document reversal must go through `voidBill`/`voidBillPayment`/`voidInvoice`/… which keep the
>    subsidiary in step. (`reverseEntryCore`, the internal path the void services use, is unaffected.)
> 3. **Finding 5 / LOW-2 hardening:** the 0023 trigger is `BEFORE INSERT` only, and
>    `journal_entries_immutable` returns early for DRAFT — so raw SQL could insert a DRAFT `EXPENSE`
>    entry with A/P lines then flip it to `JOURNAL_ENTRY`/`POSTED`. Add a `BEFORE UPDATE OF status,
>    source_type ON journal_entries` re-validation when a row becomes POSTED as a manual entry.
>
> ### Rules
> This closes the gap on BOTH A/R (ADR-018) and A/P (ADR-023); ADR-024's "the decomposition is
> complete" is corrected to scope-to-the-labelled-path pending this ticket. Test refactor: ~10
> ledger-core tests use `sourceType: 'INVOICE'` as a raw fixture via `postJournalEntry` and must move
> to `postEntryCore` (or a test-only seam) so the tightened manual path still lets them build ledger
> state. Add a release-gate regression: a document-source manual post and a document-entry reversal
> are both refused, and the A/P/A/R tie holds.
>
> ### Not in scope
> Re-architecting the manual journal API; an allowlist-based trigger (Gate 4 item 2 ratified the
> denylist form).

## §11 — End-of-ticket report

**Ticket** LL-066 — Close the control-account lock's service-layer bypasses · **Branch**
`feat/ll-066-control-lock-completeness`

**Files changed**
- `src/server/ledger/index.ts` — `postJournalEntry` now rejects any `sourceType` other than
  `JOURNAL_ENTRY` (`MANUAL_SOURCE_TYPE_REQUIRED`), before any I/O.
- `src/server/ledger/reversal.ts` — `reverseEntryCore` gains a `manualOnly` flag (default false);
  `reverseJournalEntry` passes true and the core walks the reversal chain to its ROOT, requiring a
  `JOURNAL_ENTRY` (`DOCUMENT_REVERSAL_REQUIRES_VOID`). Document voids (`manualOnly` unset) are unchanged.
- `src/server/ledger/errors.ts` — two new codes; `CONTROL_ACCOUNT_MANUAL_POST` doc reworded A/R+A/P.
- Test refactor: `adv2-concurrency`, `adv3-reversal-edge`, `ledger-concurrency`, `gl-regression` —
  `sourceType: 'INVOICE'` fixtures → `'JOURNAL_ENTRY'` (opaque source, posts to Cash/Revenue only, no
  value-assertion depended on it). `adv5-structural` S5 rewritten: a non-`JOURNAL_ENTRY` manual post is
  now the refusal it asserts, not a success.

**Migrations created**
- `drizzle/migrations/0025_control_lock_before_update.sql` — a `BEFORE UPDATE OF status, source_type`
  trigger on `journal_entries` (`assert_no_manual_relabel_to_control_account`): when an entry is/becomes
  POSTED as `JOURNAL_ENTRY`, it may not carry an A/R or A/P line — raises `CONTROL_ACCOUNT_MANUAL_POST`.
  Closes the raw-SQL DRAFT-`EXPENSE`-then-relabel vector the 0023 `BEFORE INSERT` guard could not see.
  Idempotent (`CREATE OR REPLACE FUNCTION` + `DROP TRIGGER IF EXISTS`), mirroring 0018/0023, so CI's
  clean-slate replay does not error. No column/data change. Applied to the dev branch only.

**DB constraints added** The 0025 trigger + function (above).

**Tests added**
- `manual-entry-lock.test.ts` — `postJournalEntry` refuses `EXPENSE`/`BILL_PAYMENT`/`VENDOR_CREDIT`/
  `INVOICE` (nothing posted) and still posts a `JOURNAL_ENTRY`; `reverseJournalEntry` refuses a bill's
  `EXPENSE` entry AND a bill-void's `REVERSAL` entry (the chain-root twin), but reverses a manual JE and
  re-reverses a manual reversal; the raw-SQL DRAFT-relabel is refused structurally by 0025.
- `gl-regression.test.ts` **GL-T027** — neither bypass moves the A/P control/aging (both refused, tie
  intact).

**Test results** lint ✅ · typecheck ✅ · unit ✅ 177 · build ✅. Integration + `test:gl` + `db:verify`
(0025 idempotent replay) run on CI's ephemeral branch — a local run would truncate the dev DB.

**Accounting implications** The only movers of A/R or A/P are now their documents — a manual post or
manual reversal cannot touch a control account, at the service layer and (for the relabel path)
structurally. Corrections to a document stay reversal-by-void, which keeps the subsidiary in step.

**Security implications** Closes the service-layer authz-adjacent gap where a `journal.post`-capable
actor (ACCOUNTANT/ADMIN/OWNER) could move A/R/A/P without a document. Not previously UI-reachable; now
not service-reachable either. Error codes are typed, no existence leak.

**Decisions made that were not specified in the ticket** The reversal guard checks the chain **root**
(not just the immediate source type), so a document VOID's `REVERSAL` entry — which would otherwise pass
a naive `{JOURNAL_ENTRY, REVERSAL}` allowlist — is also refused (the reviews flagged the primary case;
this closes its twin). The ledger-core test refactor swapped `sourceType` to `JOURNAL_ENTRY` rather than
moving to `postEntryCore` (less invasive, and faithful — those tests exercise the manual/core path).

**Known limitations** Opening balances (a legitimate non-document A/R/A/P mover) remain deferred — they
will need a sanctioned posting path and a trigger exception (ADR-025 revisit). The 0023/0025 triggers
stay denylist-form (Gate 4 item 2).

**Recommended follow-up** LL-067 (submit-once idempotency) next; opening-balances ticket when scheduled.
