# LL-115 — "Back to report" from a drilled-into screen

**Branch** `feat/ll-115-back-to-report` · **Status** implemented · **Origin** owner's choice for LL-115 (2026-09-27), the follow-up LL-108 recommended · **Decision** ADR-040 amendment · **Migration** none

A screen opened by clicking a report figure (LL-108) now offers "← Back to <that report>", returning to the same
report with the same filters. A chain unwinds one step at a time (balance sheet → income statement → register), and
the dashboard's headline figures lead back to the dashboard.

## §11 — End-of-ticket report

**Ticket:** LL-115 — a back-to-report link on drilled-into screens.
**Branch:** `feat/ll-115-back-to-report`.
**Files changed:** `src/app/reports/back.ts` (new: `parseBack`, `selfHref`, `withBack`, the allowed screens and titles),
`src/app/reports/drill.tsx` (`registerHref` / `incomeStatementHref` take the source address; `BackLinks` header and
`BackField` for GET filter forms), `as-of-form.tsx` (keeps `back`), every report page (header links, `back` in its
filter form, and the source reports pass their own address into their drill links), `src/app/dashboard/page.tsx`
(headline figures carry `back=/dashboard`), tests, docs.
**Migrations created:** none. **DB constraints added:** none.
**Tests added:** unit `report-back.test.ts` — accepted report screens and titles; refused: another origin,
protocol-relative, backslash, `javascript:`, non-report paths, dot-segment escapes, a relative path, an over-long value;
normalisation drops a fragment; a three-step chain unwinds; `withBack` with and without a query. E2E `reports.spec.ts`
— trial balance → register → back (as-of kept, also after the register's own filter form); balance sheet → income
statement → register and back up both steps; dashboard → aging → statement and back up both; crafted `back` values show
no link. LL-108's four drill URL assertions now also assert the exact `back` each link carries.
**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ (`npm run ci`); e2e on CI.
**Accounting implications:** none — navigation only.
**Security implications:** `back` is untrusted input from the URL; only a same-origin path to one of eight named screens
is ever rendered as a link (an allowlist, not a denylist), capped at 2,000 characters, reduced to path + query. Anything
else is ignored. Every target screen still re-authorizes (`report.view`) as before.
**Decisions made that were not specified in the ticket:** the dashboard counts as a report to go back to; the link sits
beside the existing "← Reports", which stays; the source screen's own `back` is carried in its address so chains unwind.
**Known limitations:** the journal entry and source-document screens a register row opens do not offer a way back to
the register (the browser's Back does); the entry page must stay input-free (journal e2e), which a link would not break,
but it is outside this ticket.
**Recommended follow-up:** none required.
