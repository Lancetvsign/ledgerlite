**Migrations created:** `0033_bank_reconciliation.sql` — `CREATE TYPE reconciliation_status`; two

statement date, the bank's `statement_ending_amount`, status, who/when) and `bank_reconciliation_lines`

unique for one IN_PROGRESS per account; a CHECK that COMPLETED carries completed_by/at; indexes; and
`journal_lines` gains `unique(company_id, id, account_id)` so the cleared-line FK can carry the
account. Expand-only; no data touched.

**DB constraints added:** once-only clearing of a ledger line; cleared line ∈ reconciliation's account;
one open reconciliation per account; one reconciliation per (account, statement date); completed stamp.

**Tests added:**
- `tests/integration/reconciliation.test.ts` — start rules (non-cash account, duplicate date, date not
  after last completed, second in-progress); tick list with `fromImport` after a canned import; saved ticks
  round-trip; `setCleared` rejects another account's line, a line after the statement date, a line cleared

- Two isolation descriptors in `tests/integration/isolation.test.ts`.
- `tests/e2e/reconciliation.{setup,spec}.ts` — canned import → post two lines → start Checking at

  figure shows the difference and Complete is disabled.

**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ (`npm run ci`); `db:check` clean.
Integration + e2e run on the PR's CI.

**Accounting implications:** none to the ledger — no posting, no stored balance; every figure derived
from journal lines (invariant 2). The control now exists: a statement is "reconciled" only when cleared
lines equal the bank's figure to the cent.

**Security implications:** reads `reconciliation.view` (everyone in the company), writes
`reconciliation.complete` (ALL_WRITERS); company from the session; foreign ids read as not-found;
line validation counts valid ids so a foreign line id is rejected without confirming it exists.

**Decisions made not specified in the ticket:** completed is final (no reopen in v1); statement dates
monotonic per account; whole-set save (replace) rather than per-line toggles; imported lines pre-ticked
in the UI only; no closed-period guard; ASSET+CASH only. Recorded in ADR-036.

**Known limitations:** no auto-matching of ledger lines to statement lines; no liability (credit-card)
reconciliation; no printable report; no reopen.

**Recommended follow-up:** auto-match candidates against imported statement lines by amount/date;
reopen with audit; a reconciliation report; credit-card accounts.
