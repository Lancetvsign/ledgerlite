# LL-010 — Better Auth Integration


**Branch** `feat/ll-010-authentication`

> Implement LL-010. Integrate Better Auth with the Next.js application and Neon,
> using its supported Drizzle/PostgreSQL adapter.
>
> Support account creation, login, logout, and session validation. **Do not implement
> company authorization in this ticket** — being authenticated must grant access to
> nothing.
>
> Do not hand-roll password hashing or session management. Use what Better Auth
> provides.
>
> **Schema:** Better Auth generates its own tables. Run its schema generator, then
> capture the result as a committed Drizzle migration. Auth tables are source code and
> follow the same review rules as every other migration. Do not let the auth library
> mutate a shared database schema outside the migration system.
>
> **Base URL handling is a security boundary.** Configure correctly for localhost,
> Vercel preview domains, and production using an **allowlist-based** trusted origin
> strategy. Never derive the base URL from an arbitrary `Host` or `X-Forwarded-Host`
> header — a preview domain pattern match is acceptable, reflecting whatever the client
> sent is not. Write a test that sends a forged `Host` header and confirms it is
> rejected.
>
> Secrets stay server-side. `BETTER_AUTH_SECRET` never reaches the client bundle.
>
> Create one protected and one unprotected demonstration route.
>
> **Tests:** unauthenticated request is refused; authenticated request succeeds;
> expired or tampered session is refused; logout genuinely invalidates the session
> (confirm the old cookie no longer works, not merely that a new page renders).
>
> Wire the real login into the Playwright `storageState` global setup stubbed in LL-003.
