# LL-076 — Bank-statement import (PDF → AI extract → review → post)

**Branch** `feat/ll-076a-bank-import` (076a) · **Status** 076a implemented (see §11); 076b (AI extraction)
pending · **Origin** product request: upload a bank statement (PDF in almost all cases), categorise every
credit/debit, review/confirm/change each line before entry.

> Split into two tickets. **LL-076a** — this one — builds the whole pipeline (staging tables, suggestion
> logic, the review UI, posting through the ledger) with the extractor behind a seam: production reports
> "not configured", and an env-gated canned extractor drives e2e. **LL-076b** wires the real extractor
> (local PDF text layer → Vercel AI Gateway/AI SDK structured extraction) and its dependencies. Design in
> ADR-034.

## §11 — End-of-ticket report (LL-076a)

**Branch:** `feat/ll-076a-bank-import`

**Files changed:**
- `src/db/schema/bank-import.ts` (+ barrel), `src/db/schema/ledger.ts` (`BANK_IMPORT` source),
  `src/db/schema/audit.ts` (`BANK_IMPORT_POSTED`).
- `src/validation/bank-import.ts` — extracted-row, stage, and decision schemas.
- `src/server/bank-import/{errors,extract,index}.ts` — `stageImport` / `getImportBatch` /
  `listImportBatches` / `postImportLines`, the `TransactionExtractor` seam (not-configured default +
  env-gated canned extractor), category mapping + history suggestion, dedup hashing.
- `src/app/bank-import/{page,actions}.tsx`, `src/app/bank-import/[batchId]/page.tsx` — upload + review;
  `src/app/account/page.tsx` — a `journal.post`-gated link. `playwright.config.ts` — the e2e extractor flag.
- `docs/DECISIONS.md` ADR-034; `docs/tickets/LL-076.md`.

**Migrations created:** `0031_bank_import.sql` — `CREATE TYPE bank_import_line_status`; `ALTER TYPE
audit_action ADD VALUE 'BANK_IMPORT_POSTED'`; `ALTER TYPE journal_source_type ADD VALUE 'BANK_IMPORT'`;
`CREATE TABLE bank_import_batches` and `bank_import_lines` with composite same-company FKs (batch→account,
line→batch cascade, line→suggested/chosen account, line→journal entry), `unique(batch, line_number)`, the
standing `(company_id, id)` uniques, and indexes. Expand-only; no data touched.

**DB constraints added:** the composite tenancy FKs and uniques above (a line can never reference another
company's batch, account, or entry). Post-once rides the existing `journal_entries_source_posted_once`.

**Tests added:**
- `tests/integration/bank-import.test.ts` (extractor injected — no model): stages every row with the
  category mapped to the chart; history fallback suggests the previously-confirmed account; a malformed or
  zero amount rejects the batch; a non-cash bank account is rejected; the not-configured default reports
  `EXTRACTION_NOT_CONFIGURED`; posting yields Dr bank/Cr category for money in and Cr bank/Dr category for
  money out (asserted via the trial balance) and records `journalEntryId`/`chosenAccountId`; post-once
  (re-submit is a no-op, one entry); A/R, A/P, OBE and the bank account are rejected; `ACCOUNT_REQUIRED`;
  a closed period is rejected **before anything posts**; a re-import flags duplicates; non-member denied.
- `tests/e2e/bank-import.{setup,spec}.ts` (canned extractor via `BANK_IMPORT_TEST_EXTRACTOR=1`): upload a
  PDF → review shows the suggested accounts → change one, ignore one, post → statuses update and the
  dashboard shows Checking = `1379.5000` with two recent entries; a re-upload flags all three as
  duplicates; unauthenticated redirect.

**Test results:** lint ✓ / typecheck ✓ / unit ✓ / build ✓ (`npm run ci`); `db:check` clean. Integration +
e2e run on the PR's CI.

**Accounting implications:** imports are ordinary `LedgerService` entries (invariant 8), one per confirmed
line, post-once, balances derived (invariant 2); nothing posts un-reviewed; control accounts excluded so
subsidiary reconciliation cannot be broken by an import.

**Security implications:** `journal.post` gates upload/review/post; company from the session; a cross-
company/malformed batch id reads as not-found; the uploaded file is read in memory (PDF-type + 10 MB guard)
and never stored or logged. The canned extractor is env-gated and off in production.

**Decisions made not specified in the ticket:** history matching is exact (case-insensitive) description
match over prior POSTED import lines (fuzzier matching is a follow-up); a `<select>` account picker on the
review page (server-rendered, no client JS) rather than the journal form's typeahead; per-line atomic
posting after up-front validation of every decision; `journal.post` for viewing the review (it is a posting
workflow surface). Recorded in ADR-034.

**Known limitations:** no real extraction until 076b (upload reports not-configured); no reconciliation to
invoices/bills; no scanned-PDF support; exact-match history only.

**Recommended follow-up:** **LL-076b** — local PDF text extraction (reject scans) + Vercel AI Gateway/AI SDK
structured extraction behind the same seam, the two dependencies, and the §9 data-handling note; then
reconciliation-to-documents.
