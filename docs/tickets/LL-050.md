# LL-050 — Control accounts are protected from ad-hoc manual entry


**Branch** `feat/ll-050-control-account-protection`

**Status** Backlog · **Origin** Gate 3 follow-up (accepted by the product owner) · see
**ADR-016** and [GATE-3.md](../GATE-3.md) §7 item 2.

> Close the last path that can break the A/R aging⇔control reconciliation. The aging
> (subsidiary) ties to the general-ledger A/R (control) **only because A/R is moved solely
> by invoices and payments** — GL-T018 proves the tie for that document-driven data. The
> **manual journal-entry path (LL-035) can still post to any account, including A/R**, so a
> hand-posted entry to the control account would make the control diverge from the aging
> with nothing detecting it. Gate 3 already closed the sibling path (an invoice line naming
> a control account is now rejected, `LINE_ACCOUNT_INVALID`); this ticket closes the manual
> path.
>
> ### Why this is not a one-line lock
> A blanket "no manual entry may touch A/R" is **wrong** — some manual A/R movements are
> legitimate and expected:
> - **Bad-debt write-off** — `Dr Bad Debt Expense / Cr A/R`.
> - **Opening balances** at migration onto the system — `Dr A/R / Cr Opening Balance Equity`.
>
> These must remain possible; the problem is only *ad-hoc, untracked* control-account
> entries that the subsidiary does not know about. So this is a **design decision, needing
> an ADR**, not a mechanical guard.
>
> ### Approach to evaluate (pick in the ADR)
> 1. **Sanctioned documents + default block.** Reject manual JE lines to any system control
>    account (non-null `system_account_type`) by default, and provide first-class,
>    customer-tagged document types that post through `LedgerService` and are visible to the
>    A/R subsidiary — a **bad-debt write-off** document (and, if needed, an
>    **opening-balance** import). This keeps the subsidiary⇔control tie structural because
>    every A/R movement is document-driven and countable in the aging. *Preferred.*
> 2. **Narrower capability.** Gate manual control-account entries behind a dedicated
>    capability (e.g. `ledger.post_control`). Simpler, but it does **not** restore the
>    reconciliation — an authorized manual A/R entry still breaks GL-T018 unless the
>    subsidiary is extended to include it. Weaker; document why if chosen.
> 3. **Extend the subsidiary.** Make the aging reconcile including manual A/R adjustments
>    (customer-tagged manual lines counted as subsidiary activity). Broadest change; only if
>    the product wants free-form A/R adjustments.
>
> ### Enforcement must be structural where possible
> Whatever the policy, the default block on ad-hoc control-account entry should hold **with
> the application bypassed** (a `BEFORE INSERT` trigger on `journal_lines` that rejects a
> line to a system control account unless it carries the sanctioned source type), mirroring
> the closed-period trigger (ADR-012). Sanctioned documents post with their own source type,
> which the trigger allows.
>
> ### Tests
> - A manual JE (via the LL-035 path) to the A/R control account is **rejected** — through
>   the service **and** in raw SQL (the trigger), with the service bypassed.
> - A sanctioned bad-debt write-off posts `Dr Bad Debt Expense / Cr A/R` (customer-tagged),
>   reduces that customer's open balance, and the aging⇔control reconciliation **still
>   holds** (extend GL-T018 to include the write-off path).
> - Opening-balance entries to A/R (if in scope) reconcile the same way.
> - Legitimate manual entries to **non-control** accounts are unaffected.
>
> ### Not in scope
> Customer credits / unapplied cash and multi-currency (each changes what "the A/R balance"
> means — see ADR-016 "Revisit if").
