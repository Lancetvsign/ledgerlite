# LL-034 — Trial Balance and Ledger Invariant Helpers


**Branch** `feat/ll-034-trial-balance`

> Implement LL-034: derive a trial balance, and build the reusable invariant assertions
> the rest of the product depends on. This ticket exists to *prove* that no balance is
> stored anywhere, and Gate 2 cannot be evaluated without it.
>
> ### Trial balance
> `getTrialBalance(companyId, asOfDate)` computes, **from `journal_lines` alone**, per
> account: total debits, total credits, and net balance in the account's natural
> direction. Include only `POSTED` entries. Never read a cached or stored total —
> there is none, and if you find yourself wanting one, that is the ADR-gated decision
> LL-020 warned about.
>
> Aggregate in PostgreSQL with `SUM(...)::numeric`, not by pulling rows into JavaScript.
> The database is the authoritative arithmetic engine. Return money as `string`.
>
> The trial balance must balance: total debits equal total credits across the company,
> exactly. This is a mathematical consequence of every entry balancing — if it ever
> fails, an invariant has been violated somewhere and you want to know immediately.
>
> ### Invariant helpers — used by every later ticket and every gate
>
> ```ts
> assertLedgerBalanced(companyId)      // every POSTED entry balances individually
> assertNoOrphanedLines(companyId)     // no line without an entry, no posted entry without lines
> assertAccountOwnership(companyId)    // no line references an account of another company
> assertTrialBalanceBalanced(companyId)// company-wide debits === credits
> ```
>
> Each runs as a SQL query returning violations, so it is fast enough to call at the end
> of every integration test. Wire all four into the integration test teardown so **any**
> test that corrupts the ledger fails loudly, even a test that was not written to check
> for it. This turns the entire suite into a continuous ledger audit.
>
> **Tests:** empty company; single balanced entry; many entries; entry plus its
> reversal nets to zero; `asOfDate` correctly excludes later entries; draft entries
> excluded; another company's entries excluded; four-decimal amounts summing exactly;
> and a deliberately corrupted ledger (inserted via raw SQL with triggers disabled)
> that each helper correctly detects.
