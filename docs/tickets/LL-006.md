# LL-006 — Vercel and Neon Environments, Gated Migration Deploy


**Branch** `ci/ll-006-vercel-neon-environments`

> Implement LL-006. Configure and document deployment across Local, CI, Preview, and
> Production.
>
> Production branch is `main`. Every other branch produces a Vercel Preview deployment.
>
> **Critical security requirement: a preview database must never contain live
> production financial data.** Use schema-only Neon branching plus synthetic seed, or a
> sanitized `preview-base` parent. If the native Vercel/Neon integration cannot
> guarantee this with the current configuration, implement the GitHub Actions preview
> branch alternative instead. **Copying production data into preview is never an
> acceptable fallback** — if you cannot satisfy the requirement, stop and report rather
> than proceeding.
>
> **Migration execution — read ADR and Blocker 4 carefully:**
> - **Do not put `db:migrate` in the Vercel build command for production.** Builds can
>   run more than once and can succeed without promoting, which desynchronizes schema
>   from deployed code.
> - Preview and CI: migrations run in the GitHub Actions job against the ephemeral
>   branch, before tests.
> - Production: migrations run as a discrete gated job that must succeed before the
>   production deployment is promoted. A failed migration blocks the deploy. Never
>   catch a migration error and continue.
> - The advisory lock from LL-002 applies everywhere.
>
> Configure environment variable separation across Development / Preview / Production.
> Add Better Auth placeholder variable names to `.env.example` without implementing
> authentication.
>
> Document local setup, Vercel setup, Neon setup, GitHub setup, the preview workflow,
> the production workflow, the migration workflow, and who is responsible for which
> secrets.
>
> **Acceptance — verify these, do not assume them.** Push a branch; confirm a Preview
> deployment is created; confirm it targets a non-production Neon database; make a
> schema change in Preview and confirm Production is unaffected. Report what you
> actually observed. If you could not verify a step because credentials were
> unavailable, say which step and why.
