# LL-013 — Company Authorization Layer and Server Context


**Branch** `feat/ll-013-company-authorization`

> Implement LL-013: the reusable server-side authorization layer. **Every**
> company-scoped operation in this application, now and forever, goes through it.
>
> ```ts
> requireCompanyMembership(userId, companyId): Promise<Membership>
> requirePermission(userId, companyId, capability): Promise<Membership>
> ```
>
> Both **fail closed**. Any error, any ambiguity, any missing record results in denial.
> There is no code path where an exception or a null result yields access.
>
> Return typed authorization errors, not generic ones.
>
> **Do not leak existence.** A request from Company A's user for a Company B entity must
> be indistinguishable from a request for an entity that does not exist — same status,
> same body, same timing characteristics as far as is practical. Document this in
> `/docs/SECURITY.md`.
>
> **Middleware is not sufficient.** It may exist as a convenience layer, but each
> service authorizes independently. Write down why in `/docs/SECURITY.md`: middleware
> is bypassed by any future direct service call, background job, or internal route.
>
> **Company context and switcher.** The active company lives in server-authorized
> context. A `company_id` in a cookie, URL, header, or request body is an untrusted
> input that must be validated against active membership on every single request.
> Build a simple company switcher UI showing only companies where the user has active
> membership. Keep the UI minimal.
>
> Invalid company requested → deny. **Never silently fall back to a different company** —
> that failure mode shows one tenant another tenant's data and is the worst possible
> outcome for this ticket.
>
> **Tests:** valid owner; valid bookkeeper; no membership; inactive membership; correct
> membership but insufficient capability; Company A user requesting a Company B
> resource by direct ID; forged `company_id` in a request body; forged `company_id` in a
> cookie; user with zero companies; user with many companies.
