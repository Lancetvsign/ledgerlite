# LL-065 — A/P reporting UI (UI last)

**Branch** `feat/ll-065-ap-ui`

**Status** Backlog · **Origin** Sprint 6 plan (Accounts Payable). See
[SPRINT-6-PLAN.md](../SPRINT-6-PLAN.md). The structural mirror of LL-055 (reporting UI) — **UI last
in the sprint**, pure presentation over the A/P services, **no new schema, no new service**.

> Surface the A/P domain: create and pay bills, and read the A/P aging and vendor statement.
> Mirrors the `/invoices`, `/payments`, and `/reports` patterns exactly.
>
> ### Screens
> - **Bills** (`/bills`, `/bills/new`, `/bills/[id]`) — list/detail, create + finalize + void,
>   mirroring the invoices UI.
> - **Bill payment** (`/bill-payments/new` + detail) — pick a vendor, apply to its open bills,
>   mirroring the payments UI.
> - **A/P Aging** (`/reports/ap-aging`) and **Vendor Statement** (`/reports/vendor-statement`) —
>   mirroring the A/R aging and customer statement screens; nav entries added.
>
> ### Rules
> RSC pages that call the services directly; company from the **session context**, never a query
> param; `expense.*` / `bill_payment.*` / `report.view` enforced **server-side** (forbidden reads as
> not-found). Money is **display-only** from the services' `string` values — **no JavaScript number
> touches money** (ADR-004); **extend the money-safety unit test** to the new report/UI files.
> Dates are query params validated with `isCalendarDate`. `data-testid` throughout.
>
> ### Tests
> Playwright e2e (production build, per-feature storageState): create → finalize → pay a bill; the
> **A/P aging grand total on screen equals the A/P control**; a member without the capability cannot
> reach the pages; invalid dates rejected. The money-safety grep over the new files.
>
> ### Not in scope
> A composed dashboard; CSV/PDF export; charts; scheduled/emailed reports — Sprint 7+.

**Accounting implications** None to the ledger: every screen renders the services' `string` money
verbatim; the client forms' totals are advisory (decimal.js, never a JS number) and the server
re-derives and re-posts. The aging⇔control tie the user sees on screen is GL-T026's.

**Security implications** Company always from the session context; every page and action
re-authorizes on the server (`expense.*`, `bill_payment.*`, `vendor.*`, `report.view`); a
cross-company id reads as not-found / `null`; pickers offer only in-company, active, non-control
records (a courtesy — the service is the gate). Nothing new stored.

**Decisions made that were not specified in the ticket**
1. **Added a minimal `/vendors` screen.** The spec listed bills / bill-payments / reports only, but
   the vendors *service* (LL-060) had no UI, so a fresh company's bill form could never be filled
   and the e2e could not seed a vendor — shipping that would be "complete with known failing
   behavior" (AGENTS §10). It mirrors `/customers` exactly (add + list).
2. **No `/bills/[id]/edit`** — the spec's three bill routes were honored; a DRAFT can be finalized
   but not edited via the UI (limitation below).
3. Bill line picker offers all ACTIVE **non-control** accounts (what `assertLineAccountsPostable`
   accepts), not just EXPENSE, so an asset purchase can be billed.
4. The e2e was run locally with an **ephemeral `BETTER_AUTH_SECRET` injected as a process env var**
   because `.env.local` (which I may not read/write) lacks one; nothing was written or printed. CI
   supplies its own secret.
5. Vendor-statement e2e submits an explicit wide date window (review finding: the bill is dated by
   the form's UTC today, the report by the company's today).

**Known limitations** No draft-bill edit screen. Document forms default the date to UTC today (the
pre-existing invoices/payments convention, not the company's today per ADR-007 — flagged for a
shared fix). `money()`/`requireContext`/`accountLabel` helpers are copied per feature (codebase
convention; a shared-helpers refactor is a follow-up). Bill-payment detail loads all bills to label
its applications (mirrors payments detail). No UI test of a BOOKKEEPER's hidden Void buttons (no
UI to seed a second role; server gate is integration-tested).

**Recommended follow-up** **GATE 5** (closes Sprint 6). Then: shared UI helpers refactor
(money-input, require-context, option resolution); company-today default across all four document
forms; `/bills/[id]/edit`; add `BETTER_AUTH_SECRET` to local `.env.local` (user).
