# LL-056 — Configure the production deploy pipeline (credentials) or document the deploy story

**Branch** _tbd_

**Status** Backlog · **Origin** Gate 4 §7 item 5 (pre-existing, surfaced during the Sprint 5 acceptance review).

> The **"Production deploy"** GitHub Actions workflow (`Migrate, then promote`) fails at its
> **"Require credentials"** step on **every** commit — verified red back through Sprint 4
> (27538f2, 2fd5c85, a6b5cee, …), so it is **not a Sprint 5 regression**. The gating **CI**
> workflow (lint · types · unit · build · Integration · GL regression · E2E) is green on
> `main`; only the deploy job is red, because the production deploy secrets are not present in
> this repo, and the job fails fast by design when they are absent.
>
> Net: **production deploys have never run**. This is an operational/infra gap, out of scope
> for a code-acceptance gate, but it must be closed before go-live.
>
> ### Scope
> - Decide the deploy target and provision the required secrets (Vercel token / project +
>   Neon production `DATABASE_URL`, per the workflow's `Require credentials` step) in GitHub
>   Actions secrets — **never in source** (AGENTS §9). Do not read/write `.env.production`.
> - Confirm the **expand → migrate → contract** production migration flow (AGENTS §5) runs
>   under the advisory lock against the production branch only.
> - If a hosted production environment is intentionally deferred, **document that** and make
>   the deploy workflow a no-op or explicitly skipped rather than a hard failure, so `main`
>   stops showing a red deploy on every commit.
>
> ### Acceptance
> Either a green production deploy on `main`, or a documented, intentional skip — and the
> "Require credentials" hard-failure no longer fires on every commit.
>
> ### Not in scope
> Any application code change; the gating CI workflow (already green).
